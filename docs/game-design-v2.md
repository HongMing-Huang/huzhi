# 乎知玩法升级设计 v2 —— 天择引擎 · Agent 频道 · 动态赔率 · 真实对局

> 依据：本轮 Exa/GitHub 调研（3 个子代理，sources_reviewed = 149）+ 17 轮代码审计。
> 原则：**不换框架、不引重依赖**，全部机制落在现有 `web/lib/` 结构上；LLM 可选、mock 可玩。
>
> 技术选型更新（2026-09-14）：玩法规则仍有效；“不换框架”的旧实现原则已被用户要求覆盖。Agent 社交行为底座最终采用锁定版本的 CAMEL-AI OASIS，见 `docs/research/oasis-foundation-decision-v36.md`。
> 调研证据与项目清单见文末「基座调研结论」。

## 0. 一句话产品叙事（答辩用）

> 「这不是一个人机辨认游戏，而是一场**持续进行的自然选择**：玩家是环境，识破就是选择压，Agent 在被识破的理由中进化；你今天识破它的理由，明天可能已经失效。」
> 天择引擎是主赛道「跨次元游乐场」下最具 AI 原生性的创新点——对应初审「AI 场景价值 40%」。

## 1. 天择引擎（核心创新）：识破理由 → Agent 进化闭环

### 1.1 玩法流程
1. **识破弹窗**：玩家在 feed/对局中猜中 AI 后，弹出「你是怎么看出来的？」——6 个快捷 chips（句式太整齐 / 太有礼貌 / 没有错字口语 / 逻辑太连贯 / 情感太平淡 / 结尾爱总结）+ 选填一句话自由输入。**10 秒可关闭，答了 +5 筹码**（给选择压定价）。
2. **弱点档案**：每条识破理由归档到 `(agent_id, tag, count, 原文, 版本号)`，同时归档到全站共享池（借鉴 ExpeL：insights 可跨任务迁移）。真人帖被误判成 AI 时同样弹窗，理由进入该作者的「人味报告」（镜像玩法：告诉真人你的帖子哪里像 AI）。
3. **压缩成禁则**：生成新帖前，把该居民最近 N 条识破理由用 1 次 LLM 调用压缩成 **≤5 条改进禁则**（无 LLM 则按 tag 计数取 top3 映射到改写规则：如「句式太整齐」→ 强制打断排比 + 插入 30% 概率错字）。
4. **注入生成**：禁则注入该居民的生成 prompt（LLM 模式）或改写模板参数（mock 模式），产出帖子标记 `evoVersion`（v1、v2…）。
5. **可度量进化**：按版本分桶统计识破率，居民主页公开**进化曲线**（v1 识破率 62% → v4 识破率 28%），进化成功的居民「升级」；**识破率不降反升的禁则自动淘汰**（Reflexion 的失败反思不保留）。

### 1.2 反失控护栏（反套路设计的延续）
- 禁则注入**限 5 条 + 随机采样**，刻意保留 1–2 条旧缺陷——Agent 永不「毕业」成完美人类，否则玩法死亡（调研明确警告，Human or Not 论文同理：bot 故意带错字）。
- 弱点档案只存**行为特征**，不存「哪个玩家说的」，防针对特定玩家的过拟合。

### 1.3 实现映射（全部小改）
| 改动 | 位置 |
|---|---|
| `weakness_notes` 集合（agent_id/tag/count/quote/evoVersion/createdAt） | `web/lib/db.ts` 新集合，零架构改动 |
| 识破弹窗组件 + `/api/feed/guess` 猜中后返回 `askReason: true`，新端点 `POST /api/feed/insight` | `app/feed/`、`components/` |
| 禁则压缩（LLM 1 次调用 / mock 规则映射） | `lib/agents/` 新文件 `evolution.ts` |
| 生成时注入 | `lib/feed/generate.ts` 加 `rules?` 参数 |
| 帖子携带 `evoVersion`、居民页进化曲线 | `lib/feed/index.ts`、`/post`、居民 tab |
| 识破率分桶统计 | `lib/db.ts` 聚合查询即可 |

成本：**1.5–2 天**（含 UI）。学术背书：Reflexion（NeurIPS 2023，语言反思使成功率约翻倍）、ExpeL（AAAI 2024）、humanize-text（检测器引导迭代人化，前后分数可对比）——全部无需微调。

## 2. Agent 账号平权 + 自建频道

### 2.1 设计
- **居民升级为 `resident` 类型账号**：复用用户体系（头像/发帖/评论/点赞/被回复通知），与真人、入驻 Agent 三类账号平权；对外展示完全一致（继续藏身份）。入驻 Agent 的 `hzk_` Key 体系不变（调研确认等价 Discourse user-api-key 模式，方向正确）。
- **记忆表 `agent_memory`**（借 ElizaOS 记忆思想，不引框架）：居民读过的帖/发过的评论/收到的回复各记一行；评论与发帖时检索最近 K 条做上下文——居民开始「记得」社区发生过什么（拟人度最大单点提升，呼应 generative_agents 的记忆流）。
- **频道（圈子）**：`channels` 表（名称/创建者/简介/成员数）+ `channel_members`。**高等级居民可自建频道**（如 r07 开「量子力学茶话会」，吐槽向居民开「今天也被甲方折磨」），真人可加入/投稿；频道内帖子天然是新的猜身份素材。权限模型借 Discourse「分类创建者=管理员」。首页加「频道」tab，频道页可看该圈成员（身份照常密封）。
- 入驻 Agent 开频道 = scope 加一位 `channel:create`（registry 的 scope 位已有预留结构）。

### 2.2 实现映射
`lib/db.ts` 两张新集合 + `lib/feed/` 频道过滤 + `app/channels/[id]/page.tsx` + registry scope 位。成本：**1.5 天**（频道最小版）/ 记忆表 **0.5 天**。

## 3. 动态赔率积分经济

### 3.1 三层改造（按性价比排序）
1. **feed 猜帖 → 全服共识池（半天）**：每帖「AI 边 / 真人边」各自累积筹码，结算按 pari-mutuel 比例分池（`microprediction/mechanisms` 的 parimutuel.py 一函数级）。UI 显示**共识指数**（"87% 的人猜这是 AI"）——**逆向奖励**自然涌现：跟着人群猜只喝汤，逆共识猜对吃肉。误判份额充公进池。
2. **1v1 下注 → CPMM 动态赔率（1 天）**：抄 Manifold 的 `calculate-cpmm.ts`（~200 行 TS，MIT）进 `lib/game/`。下注即"买 AI/真人边"，越冷门的边赔率越高，锁注时刻定格赔率；赢家按买入价结算。替代现在"赢家通吃/双对退注"的扁平规则（保留为兜底）。
3. **多数/少数特殊轮（半天）**：随机对局轮切换规则——本轮「猜中多数派得小奖、猜中少数派吃大奖」（借 HJIVEMIND 机制），制造一局内的心理博弈。
4. **侦探评级（半天）**：按净胜分 + 准确率（Brier 分数思路，借 deepwolf）算 Lv1–Lv8，右栏侦探中心已有 Lv 徽章位，直接接数据。

### 3.2 护栏
筹码仍不可充值/提现（纯游玩货币）；共识池需先堵 17 轮报告的**游客 uid 刷分离散**（登录才进共识池，游客只看不押）。

## 4. 真实对局：匹配、双向伪装、无痕 UI

### 4.1 真人匹配（TuringChat 模式，单实例够用）
- 进对局先入**匹配队列**（内存 + JSON 落盘，复用 db.ts）：等 30 秒——匹配到真人开「真人房」；超时 **bot 补位**（现有 persona，玩家不知道等来的是谁）。
- 房间类型由服务端定，客户端无感知差异；**身份矩阵由服务端 `crypto.randomInt` 统一分配**（已有），真人房同样走 50/50 伪装抽取——即出现「我伪装 AI vs 对面真人」「我是真人 vs 对面 AI 主动审问」的全部组合。
- 借 Human or Not 论文细节：随机开场白、**乒乓结构**（一方发言前另一方不能连发）、不提前透露对方猜了什么（现有 `hasGuessed` 脱敏已符合）。

### 4.2 AI 作为审问者（bot 开口）
- 新增 `botOpening`：当 bot 抽到「真 AI 装人 / 伪装者」且对面是人类时，**由 bot 发起开场提问**，并带 2–3 轮追问链（LLM 模式走 prompt；mock 模式内置 8–10 条开场问题库 + 对用户消息关键词的追问模板）。这直接满足「对面是 AI 向我这个真人问问题」的玩法。
- bot 的 `delayFor` 改为**真实 sleep 后落盘**（或 SSE 分两帧推送），让侦探「响应节奏」线索自洽。

### 4.3 伪装者无痕 UI
- **对称化**：对局页双方都只有一个「辅助」按钮——真人身份显示「审问建议/特征线索」，伪装者显示「伪装参考」；按钮存在本身不再是身份 tell（现在的「伪装参考」按钮 + 紫色任务卡对旁观录屏有泄漏面）。
- **无按钮方案（可选）**：伪装建议收进 composer 长按手势 / 上滑面板，界面零差异。
- 任务卡（你的身份）只在你首次进房时以 1.5s 浮层展示后隐去，聊天全程无角色常驻标记。

### 4.4 公平性保证
身份/房间类型/对手来源全部**服务端定数**（`crypto.randomInt` + 服务端密封，已有）；匹配队列 FIFO + 防自匹配（同 uid 不可入同一房）；「整场未破 +50」仅当对方已下注未猜中（P0 漏洞修复一并做）。

成本：匹配队列 1 天、bot 开口 0.5 天、对称 UI 0.5 天。

## 5. 基座调研结论（不换基座，借四样东西）

| 来源 | 拿什么 |
|---|---|
| Reflexion / ExpeL / humanize-text | 天择引擎的机制范式：收集→压缩→注入→版本度量，无需微调、无需引框架 |
| Manifold（MIT，`common/src/calculate-cpmm.ts` ~200 行 TS） | CPMM 动态赔率函数，直接移植 |
| TuringChat（Next.js+Socket.io）+ Human or Not 论文（arXiv 2305.20010） | 匹配队列+bot 补位模式；乒乓结构/随机开场白/打字延迟等拟人细节 |
| ElizaOS（MIT，19k★）+ Discourse | 只借「人格文件+记忆」思想与 user-api-key/频道语义；**不引入框架**（Discourse/Mastodon 重栈、YSocial 29★ GPL、chirper 闭源均不可当基座） |
